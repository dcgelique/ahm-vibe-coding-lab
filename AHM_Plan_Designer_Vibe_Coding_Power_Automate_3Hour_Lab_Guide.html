Workshop overview

Build one connected solution: use Plan Designer to structure the idea, create an app at vibe.powerapps.com, store requests in Dataverse, and use Copilot in Power Automate to create the approval workflow.

1. Plan

Define personas, process, data, app, automation, and success criteria.

2. Build

Generate and refine the request app and confirm it creates Dataverse rows.

3. Automate

Trigger a cloud flow when a request row is created, route an approval, update the row, and notify the requester.

Scenario

An AHM team member identifies a non-critical operations improvement opportunity and submits a structured request. A designated reviewer approves or rejects the request. The app and flow record the decision and notify the requester. Use synthetic workshop data only.

Plan Designer→Power Apps Vibe→Dataverse row→Power Automate approval

Lab 1 | Plan the solution

Time: 30 minutes. Use Plan Designer to convert the business requirement into a structured solution plan.

Step 1. Start a new plan

1

Open Power Apps

Sign in with the provided workshop account and select the assigned environment.

2

Open Plan Designer

Create a new plan and choose the option to describe the business requirement.

Step 2. Enter the planning prompt 

Create a solution for managing operations improvement requests across Astra Honda Motor teams. Employees should submit improvement opportunities with a request title, area, category, description, expected benefit, priority, requester email, and approver email. Managers should review each request and approve or reject it. Approved requests can move to In Progress and eventually Closed. Use Dataverse to store requests. Include an employee-facing app, an approval workflow, status notifications, and a dashboard showing requests by area, status, and priority. Use synthetic workshop data only.

Lab 2 | Build with Power Apps Vibe

Time: 55 minutes. Generate the app, inspect the proposed data, test the smallest complete path, and refine deliberately.

Step 1. Generate the starting point 

Create an Operations Improvement Request app for an AHM workshop. Employees can submit and track requests. Store the data in Dataverse. Capture Request Title, Area, Category, Description, Expected Benefit, Priority, Requester Email, Approver Email, Submitted Date, Status, Decision Comments, and Resolution Notes. Include a New Request form, My Requests page, Request Details page, and dashboard. Make Request Title, Area, Category, Description, Expected Benefit, Priority, Requester Email, and Approver Email required. Set newly submitted requests to Submitted. Use an accessible layout for laptops and tablets and synthetic workshop data only.
1

Open vibe.powerapps.com

Select the same environment used for the plan.

2

Paste the prompt

Review the plan, tables, relationships, and screens before generating.

3

Generate the app

Wait for the app and Dataverse structure to be created. Do not accept unexpected components without review.

Step 2. Refine the app

Use one prompt at a time and test after each change.

Improve the form 

Make the New Request form easier to complete. Group requester information separately from request details. Show required-field indicators and clear validation messages.

Create My Requests 

Add a My Requests page that filters records using the signed-in user's email. Display request title, priority, status, submitted date, and area.

Protect workflow fields 

Make Status, Decision Comments, and Resolution Notes read-only for regular requesters. Show status using an accessible badge that includes text and does not rely only on color.

Step 3. Test the application

Mandatory checkpoint: The Power Automate lab begins only after the app can create a Dataverse row containing Requester Email, Approver Email, Status, and the request details.

Lab 3 | Build the flow with Copilot in Power Automate

Time: 50 minutes. Create an automated cloud flow that runs when a new request row is created.

Step 1. Ask Copilot to create the flow 

Create an automated cloud flow that runs when a new Operations Improvement Request row is added in Dataverse. Update the request status to Pending Approval. Start and wait for an approval using the Approver Email from the record. Include the request title, area, description, expected benefit, priority, and requester email in the approval. If approved, update the status to Approved. If rejected, update the status to Rejected. Save the approver comments into Decision Comments and send the requester an email with the result.

Step 2. Validate every generated action

Flow elementRequired configuration
Dataverse triggerWhen a row is added, modified or deleted; Change type: Added; Scope: Organization; select the generated request table.
Update rowUse the trigger Row ID. Set Status to Pending Approval.
ApprovalApprove/Reject, first to respond. Assigned to the Approver Email dynamic value.
ConditionCompare approval Outcome with Approve.
Yes branchUpdate the same row to Approved, save comments, notify requester.
No branchUpdate the same row to Rejected, save comments, notify requester.
If the app creates Draft rows: do not trigger approval on creation. Use a Modified trigger and start only when Status becomes Submitted. This prevents approvals for unfinished drafts.

Troubleshooting

ProblemWhat to check
The flow does not startConfirm the environment, table, Change type, Scope, saved state, and that a new row was actually created.
The approval is not receivedCheck Approver Email, connection status, approval action inputs, and the flow run history.
Update row failsConfirm the Row ID is from the Dataverse trigger and choice values match the Dataverse Status options.
The flow triggers repeatedlyUse Added only, or add a trigger condition for Status = Submitted. Ensure updates do not satisfy the trigger again.
Requester email is blankInspect the Dataverse row and confirm the Vibe app writes Requester Email before submission.
Generated app contains extra componentsRemove or ignore out-of-scope components. Keep the workshop focused on one app, one table, and one flow.
